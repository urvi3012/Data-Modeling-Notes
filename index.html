Data Modeling for Data Engineers

Data modeling isn't just about drawing boxes; it's about optimizing data for human and machine consumption. We move from High-Write systems to High-Read systems.

1. OLTP vs OLAP: Detailed Comparison

Based on AWS Architecture Standards, here are the fundamental differences between transactional and analytical systems:

Feature OLTP (Transactional) OLAP (Analytical)
Main GoalData Processing (Recording transactions)Data Analysis (Decision making)
Data SourceOperational databases (ERP, CRM)Data Warehouse / Data Lake
Data ModelNormalized (3NF) - eliminates redundancyDenormalized (Star/Snowflake) - fast joins
Processing SpeedMilliseconds (Fast updates/writes)Seconds to Hours (Massive read scans)
ConcurrencyHigh (Thousands of simultaneous users)Low (Small teams of analysts/BI tools)
Backup/RecoveryMission critical, needs frequent backupsLess critical, data can be re-run from source
Example Query"Insert customer order #552""Total revenue growth per region in Q4"

3. From OBT to Dimensional Gold

In the Silver Layer, we often build One Big Table (OBT). This is a massive, denormalized table containing everything needed for cleaning.

Why split OBT into Gold?

While OBT is great for simple scripts, Dimensional Modeling (Facts and Dims) in Gold allows:

  • Space Efficiency: Product details are stored once in a Dimension, not repeated a million times in the Fact.
  • Conformed Consistency: Using the same 'Date' table for Sales and Shipping prevents metric discrepancies.
