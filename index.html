1. The Fundamentals

Data modeling is the architectural blueprint of how data flows and resides. For Data Engineers, the focus is query performance and scalability.

  • Conceptual: Business entities (Customer, Product). No tech details.
  • Logical: Defining attributes and relationships (PK/FK).
  • Physical: Actual DB implementation (Data types, Indexes, Partitioning).

2. OLTP vs OLAP

Feature OLTP (Transactional) OLAP (Analytical)
Focus Fast Writes (CRUD) Fast Reads (Aggregation)
Normalization Highly Normalized (3NF) Denormalized (Star/Snowflake)
Redundancy Eliminated Accepted for performance

4. Dimensional Modeling

Fact Tables vs Dimension Tables

In the Gold layer, we split data into Facts (Quantitative) and Dimensions (Qualitative).

Fact Sales

sale_idprod_keyamount
1011$50.00

Dim Product

prod_keynamecategory
1LaptopElectronics

Surrogate Keys: Always use an internal integer (1, 2, 3) as a primary key instead of a business ID (like Email) to protect your model from source system changes.

5. Star vs Snowflake

Star Schema

Dimensions connect directly to the Fact table. High performance, less joins.

Fact -> Dim_Product

Snowflake Schema

Dimensions are normalized into sub-dimensions. Saves space, but slower queries.

Fact -> Dim_Product -> Dim_Category
